# Библиотека сортировок

📝 Надо реализовать библиотеку сортировок в виде **dll** библиотеки. Написать тесты для всех сортировок, используя фреймворк **googletest**.

📂 Создана архитектура проекта. Все файлы пустые, кроме `build.bat`. Кто использует **linux**-подобные ОС, напишите аналогичный `build.sh` файл.

🛠️ Надо скачать **cmake** и **ninja**. Это стандратное ПО. Его можно скачать из пакетных менеджеров. Также надо выкачать с **github** репозиторий **googletest**. Все сторонние библиотеки кладём в папку `lib` и эту папку добавляем в `.gitignore`.

## Задание

⚠️ Все сортировки можно положить в один модуль `sort.hpp/sort.cpp`, но тесты пишем для каждой сортировки в отдельном `test_name.cpp` файле и компилируем в отдельный **exe** файл.

В библиотеке реализуем все пройденные сортировки (и этот список ещё будет пополняться):
1. Классический пузырёк.
2. Оптимизированный пузырёк с выходом, если за время прохода по массиву не произошло ни одного обмена.
3. Пузырёк из `пункта 2`, но с оптимизацией правой границы. Т.е. за один проход по массиву правая граница уменьшается не на `1`, а принимает значение места последнего обмена.
4. Шейкерная сортировка.
5. Шейккерная сортировка с оптимизацией правой границы.
6. Чёт-нечет сортировка для однопоточного варианта программы (пока ещё не доросли... 😞 ).
7. Сортировка расчёской.
8. Сортировка выбором.
9. Сортировка вставками.
10. Сортировка Шелла.
11. Продолжение следует...

Отдельной программой надо:
1. Создать массив на `10 000`, `100 000`.
2. Для каждой сортировки создать копии этого массива и замерить время сортировки на вашем компьютере.
3. Оформить результаты в файле **MarkDown**.

⚠️ В папке `test` я сохранил пример подключения бииблиотек в файле `cpp` и `CMakeLists.txt` сборки теста. (Внимание: `gmock` не подключаем.) Для каждой сортировки реализуйте 3 разных тестовых случая (сейчас в примере `test_bubble_sort_classic.cpp` описан один `Equal, without_equal_elemens`).
